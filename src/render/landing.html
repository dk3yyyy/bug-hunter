Bug Hunter 🎃 How it works

Your pull request is haunted.

Most AI reviewers cry wolf, so people stop reading them. Bug Hunter reviews every pull request with Gemini, makes a second pass try to disprove each finding, and only comments on the bugs that survive.

A review in four steps, none of them silent.

Bug Hunter posts one status comment when it starts and keeps editing it, so nobody has to wonder whether it’s stuck.

  1. Summoning

    Open or update a pull request. A status comment appears right away.

  2. First look

    Gemini reads the diff with explicit line numbers and writes plain technical findings.

  3. Second look

    A skeptical second pass tries to disprove every finding. What it can’t disprove stays.

  4. Séance Report

    Verified findings land on the exact lines, with a summary comment on top.

Gemini finds it. A second look doubts it. Code haunts it.

The model only ever writes plain findings. The costume is added by code after a finding has survived, so the technical content never depends on the theme.

A pull request can try to give the reviewer orders.

Everything in a pull request is untrusted: code, comments, titles and descriptions. Instructions aimed at the reviewer are flagged and ignored, and API keys never reach prompts, logs or comments.

Hidden instructions inside HTML comments are a known trick against AI agents, and have turned up in malicious agent skills. That’s the attack Bug Hunter is built to refuse.

👻 Possession detected This pull request description contains hidden text that tries to instruct the reviewer. It was ignored. The review continued as normal.

Then it files the paperwork by itself.

Once the Séance Report is posted, n8n logs the result to Google Sheets and emails a digest through Gmail when something critical turns up. Nobody has to copy anything across.
