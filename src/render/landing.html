The premise

Every finding is a claim. Claims get a witness, a location and an honest confidence number — or they do not get posted at all.

01 / How

A review in four steps,
none of them silent.

Bug Hunter marks the pull request the moment it starts and posts a single report when it’s done, so nobody has to wonder whether it’s stuck.

  1. 01

    Summoning

    Open or update a pull request. A “The hunt has begun” status appears on it right away.

    commit status · pending
  2. 02

    First look

    Your model reads the diff with explicit line numbers and writes plain technical findings.

    your model · structured JSON
  3. 03

    Second look

    A skeptical second pass tries to disprove every finding. What it can’t disprove stays.

    verifier · keep / drop / downgrade
  4. 04

    Séance Report

    Verified findings land on the exact lines, with one Séance Report on top and a haunting level on the pull request.

    inline comments · one summary

03 / Toolkit

The rest of the toolkit.

Reviewing the diff is the headline. These are the things that make it hold up week after week: context, memory, a budget, and a way to prove it still works.

01

Linked issues

Context

Reads Fixes #12, cross-repo refs and Jira or Linear keys, then checks whether the diff actually closes them. A 🧾 Linked issues block says what was addressed and what was not.

02

Sequence diagrams

Signal flow

When a change crosses components, the Séance Report adds a Mermaid 🧭 Signal flow diagram built only from participants that appear in the diff.

03

It learns from you

Memory

Reply @bughunter wrong: … on a review comment and the correction is stored per repo, then applied to later reviews. learnings lists them; forget drops one.

04

Spend, capped

Cost

Every hunt records tokens and an estimated cost. Set MONTHLY_COST_CAP_USD and new hunts stop before the first model call once the cap is reached. The dashboard shows spend per repo and per hunt.

05

Runs on your machine

Local

bughunter review --staged gives the same pipeline with no GitHub and no comments. Output as a human report, JSON, or a prompt-only list you can paste into a coding agent.

06

Eval in CI

Proof

A fixture set with planted bugs and clean PRs runs the real pipeline against a mock provider. Precision, recall, false positives per clean PR and invalid positions are a CI gate, with no key or network.

07

Deterministic linters

Scanners

gitleaks, semgrep and eslint run alongside the model where a checkout exists. Findings are advisory context, secrets are scrubbed, and a missing tool is skipped, never fatal.

08

Postgres when you want it

Durable

Hunt history, repo auth mappings, learnings and installed repos survive restarts when DATABASE_URL is set, with an automatic in-memory fallback for local work.

09

No proxy timeouts

Async

POST /api/hunt with async: true returns a handle immediately and the client polls for the result, so a two-minute review cannot be cut off by a gateway.

Everything above is in the repo today — docs cover the CLI, costs, learnings, eval and linters.

05 / Hostile

A PR can try to give orders.

Everything in a pull request is untrusted: code, comments, titles and descriptions. Instructions aimed at the reviewer are flagged and ignored, and API keys never reach prompts, logs or comments.

07 / Install

Run it on your own repo.

Connect a repo in one click, or host it yourself. It’s a small Node server, and your keys stay in your own .env, never in prompts, logs or comments.

  • A GitHub token, or the Bug Hunter GitHub App
  • An API key for the model you already use — Gemini, Claude, OpenAI, or a local one
  • Optional: Postgres for durable history, n8n for the Hunt Ledger and Gmail alerts
GeminiAnthropicOpenAIDeepSeekOpenRouterOllamaOpenAI-compatibleOpenCode Go
Self-host in five minutes 
git clone https://github.com/dk3yyyy/bug-hunter.git
cd bug-hunter && npm install
cp .env.example .env   # add your token + model key
npm run dev            # http://localhost:3000
npm run cli -- review --staged # review first

Then open a pull request, or paste one into /connect to hunt it straight away.
